B2B Enterprise Federation & Provisioning Gateway

Live demo — SCIM directory sync, OIDC federated login, and an ABAC-enforced reverse proxy, all running for real against the acme demo tenant. No mocked responses: every action below hits the actual gateway.

1 · SCIM directory sync

Simulates an identity provider (Okta, Entra ID, Ping) pushing a new employee into the gateway via SCIM 2.0 — the same protocol a real corporate IdP uses for automated provisioning/deprovisioning.


  


  

    
2 · OIDC login + ABAC-enforced proxy

    
Signs you in through a mock corporate OpenID Provider (a stand-in for Okta/Entra/Auth0), then calls a backend resource through the gateway's reverse proxy. Every call is evaluated against a real ABAC policy before it's allowed through.

3 · SAML 2.0 (SP-initiated SSO)

    
The gateway also speaks SAML — a hand-rolled SP with real XML-DSig signature verification (including anti-signature-wrapping defenses). This flow needs a signed assertion minted by an IdP, which means real cryptographic signing — not something a static page can automate safely, so it's a guided curl walkthrough instead of a button.

    

      Show the SAML walkthrough
      
curl -D - -o /dev/null "https://b2bfp.syntagmata.com/saml/acme/login?returnTo=/api/reports/dashboard"
